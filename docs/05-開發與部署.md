# 05 — 開發與部署

## 1. 本機開發

### 1.1 需求

- .NET SDK 10.0.401（`global.json` 指定，允許 latestPatch；會先找 repo 內 `.dotnet/`，再找系統安裝）
- 可連線的 SQL Server：`ReportCenter`、`PKSYS` 兩個資料庫
  （開發 DB 版本可以較新，但寫 SQL 必須相容 2008 R2，見 [04](04-資料庫.md)）
- 不需要 Node / npm

### 1.2 連線字串（User Secrets）

開發環境的連線字串放在 User Secrets（`UserSecretsId = bfde3c30-2869-44bb-9ffe-191ccf1860c0`），不進版控：

```bash
cd ReportCenter.Web
dotnet user-secrets set "ConnectionStrings:ReportCenter" "Server=...;Database=ReportCenter;Integrated Security=True;TrustServerCertificate=True;"
dotnet user-secrets set "ConnectionStrings:PKSYS" "Server=...;Database=PKSYS;Integrated Security=True;TrustServerCertificate=True;"
```

> 開發環境啟動時不會檢查連線字串；沒設的話，第一次用到 Repository 才會拋「缺少 ConnectionStrings:… 設定」。

### 1.3 啟動

```bash
cd ReportCenter.Web
dotnet run
```

- 網址：`http://localhost:5276`（https：`https://localhost:7276`）
- `ASPNETCORE_ENVIRONMENT=Development`（`Properties/launchSettings.json`）
- `.claude/launch.json`、`.codex/environments/environment.toml` 也是同樣的啟動指令

### 1.4 開發環境的特殊行為

| 項目 | 開發環境 | 測試 / 正式 |
|------|---------|------------|
| 身分 | `DevWindowsAuthMiddleware` 依 `MockWindowsAuth` 模擬（預設 `PROSKIT\10255` 高先生 / 資訊部 109） | IIS Windows 驗證 |
| 首頁戰情 | `MockHomeDashboardRepository` 假資料 | SP `usp_Rpt_Home_YtdTarget` |
| 管理員 | `appsettings.Development.json` 的 `AdminUsers`（`10308`、`10255`） | `RC_CONFIG_PATH` 檔的 `AdminUsers` |
| 診斷頁 | `/_diag/windows-auth` 開啟 | 預設關閉 |
| 例外 | Developer Exception Page | `/Error` 頁 + log |
| 日誌 | Console | File + Seq |

**切換身分測試**：改 `appsettings.Development.json` 的 `MockWindowsAuth`（`UserName`、`EmployeeId`…）後重新啟動。例如：

- 測一般使用者：把 `EmployeeId` 改成不在 `AdminUsers` 內的員編 → 只會看到有授權的報表、看不到系統管理。
- 測無權限者：用一個沒有任何授權的員編 → 所有部門 0 筆。

### 1.5 建置

```bash
cd ReportCenter.Web
dotnet build
```

目前專案**沒有自動化測試專案**。

## 2. 環境與設定檔

| 環境 | `ASPNETCORE_ENVIRONMENT` | 設定來源 |
|------|-------------------------|---------|
| Development | `Development` | `appsettings.json` + `appsettings.Development.json` + User Secrets |
| Staging | `Staging` | `appsettings.json` + `appsettings.Staging.json` + 外部機密檔 |
| Production | `Production`（未設定時的預設值） | `appsettings.json` + `appsettings.Production.json` + 外部機密檔 |

`web.config` 沒有設定 `ASPNETCORE_ENVIRONMENT`，因此 IIS 上預設就是 **Production**；若要架 Staging，需在 `web.config` 的 `<environmentVariables>` 或 IIS 設定中加上 `ASPNETCORE_ENVIRONMENT=Staging`。

### 2.1 外部機密檔

非開發環境由 `web.config` 的環境變數指定兩個 JSON 檔（後者覆蓋前者）：

| 環境變數 | 目前 `web.config` 的值 | 內容（範本） |
|----------|----------------------|-------------|
| `SHARED_INFRA_PATH` | `C:\CompanySecrets\shared-infra.Production.json` | `ConnectionStrings:PKSYS`、`Seq:ServerUrl`、`Seq:ApiKey` |
| `RC_CONFIG_PATH` | `C:\CompanySecrets\reportWebApp-Site.Production.json` | `ConnectionStrings:ReportCenter`、`AdminUsers` |

範本在 `ReportCenter.Web/docs/開發/*.template.json`（路徑與 `web.config` 一致為 `C:\CompanySecrets\`；若伺服器實際放在其他磁碟，請同步修改 `web.config`）。

- 環境變數有設但檔案不存在 → **啟動失敗**。
- 兩個連線字串任一缺少 → **啟動失敗**。
- 啟動失敗的原因會寫在 Bootstrap Logger（Console）；IIS 上要看可暫時把 `web.config` 的 `stdoutLogEnabled` 改成 `true`，輸出到 `logs\stdout*`。

## 3. IIS 部署

### 3.1 伺服器前置

1. 安裝 .NET 10 **ASP.NET Core Hosting Bundle**。
2. 安裝 IIS「Windows 驗證」功能：伺服器管理員 → 新增角色及功能 → Web 伺服器 (IIS) → 安全性 → Windows 驗證。
3. 站台驗證設定：**啟用 Windows 驗證、停用匿名驗證**。
   `web.config` 沒有包含這兩項設定（`<security><authentication>` 區段在 IIS 預設是鎖定的，寫進 `web.config` 反而會造成 HTTP 500.19），請在 IIS 管理員對站台設定。
   應用程式本身已設定 FallbackPolicy：就算匿名驗證沒關，未驗證請求也只會收到 401，不會被放行。
4. 建立外部機密檔（§2.1），並確認 App Pool 身分有讀取權限。
5. 資料庫：
   - App Pool 身分（若連線字串用 `Integrated Security`）需有 ReportCenter 讀寫、PKSYS 讀取、執行 `usp_Rpt_Home_YtdTarget` 的權限。
   - 新環境先執行 `db-ddl.sql`。
6. 站台目錄下 `logs\` 需讓 App Pool 身分可寫入（Serilog File Sink）。

### 3.2 發佈

```bash
cd ReportCenter.Web
dotnet publish -c Release -o ./publish
```

將 `publish/` 內容複製到 IIS 站台目錄（`web.config` 已隨專案輸出，`hostingModel="inprocess"`、`forwardWindowsAuthToken="true"`）。

> repo 中的 `.github/workflows/deploy.yml` 是早期前端版本遺留的 GitHub Pages（npm build）流程，**與目前的 .NET 專案無關**，不能用來部署。

### 3.3 部署後檢查清單

1. 開首頁，頂欄顯示的姓名 / 暱稱正確（代表 Windows 驗證 + PKSYS 查詢成功），公司別預設為使用者所屬區域。
2. 管理員帳號側欄出現「系統管理」，一般帳號沒有。
3. 首頁三張 KPI 卡有真實數字（代表 SP 可執行）。
4. 點一張報表後，到 `/Admin/Usage` 明細查得到這筆點擊。
5. `logs\rc-YYYYMMDD.log` 有寫入；有設 Seq 的話 Seq 上看得到事件。

### 3.4 身分問題排查

若出現「名字顯示成員編」「看不到報表」「管理員進不了管理頁」：

1. 在外部機密檔設定 `"WindowsAuthDebug": { "Enabled": true }`，回收 App Pool。
2. 開 `/_diag/windows-auth`，檢查：
   - `IsAuthenticated` 是否為 true、`AuthenticationType` 是否為 Negotiate
   - 正規化帳號是否等於員編
   - PKSYS 是否查得到（`PksysUserFound`、錯誤訊息）
   - `UserInfo.Id` 是否在 `AdminUsers` / 是否有授權
3. 排查完**務必關閉**診斷頁。

## 4. 日誌查詢

- 檔案：`{站台目錄}\logs\rc-YYYYMMDD.log`，保留 30 天。
- 每行格式：`時間 [等級] [來源類別] TraceId=… User=… 訊息`
- 使用者回報錯誤時，請對方提供錯誤頁上的 **TraceId**，用它搜尋 log / Seq。

## 5. 開發規範摘要

完整規範見 `CLAUDE.md`「開發規範」與 `AGENTS.md`，重點：

- UI 文字、註解、commit message 使用繁體中文。
- 商業邏輯放 `Services/`，資料存取放 `Repositories/`，View 只負責呈現。
- 樣式用 Tailwind utility，互動用 Alpine；複雜 Alpine 邏輯寫成 `function xxxPage()` 放在 `@section Scripts`。
- 新增報表連結務必加上 `data-report-id`、`data-report-source`（否則不會記錄使用）。
- 新增任何「取得部門」的方法務必套用 `DepartmentDisplay` 白名單過濾。
- 新管理頁一律繼承 `AdminPageModel`。
- 所有 SQL 相容 SQL Server 2008 R2。
