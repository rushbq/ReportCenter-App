# 05 — 開發與部署

## 1. 本機開發

### 1.1 需求

- .NET SDK 10.0.401（`global.json` 指定，允許 latestPatch；會先找 repo 內 `.dotnet/`，再找系統安裝）
- 可連線的 SQL Server：`ReportCenter`、`PKSYS` 兩個資料庫
  （開發 DB 版本可以較新，但寫 SQL 必須相容 2008 R2，見 [04](04-資料庫.md)）
- 不需要 Node / npm
- Tailwind CSS standalone CLI v3.4.17（建置時編譯 CSS 用，見 1.6）

### 1.2 連線字串（User Secrets）

開發環境的連線字串放在 User Secrets（`UserSecretsId = bfde3c30-2869-44bb-9ffe-191ccf1860c0`），不進版控：

```bash
cd ReportCenter.Web
dotnet user-secrets set "ConnectionStrings:ReportCenter" "Server=...;Database=ReportCenter;Integrated Security=True;TrustServerCertificate=True;"
dotnet user-secrets set "ConnectionStrings:PKSYS" "Server=...;Database=PKSYS;Integrated Security=True;TrustServerCertificate=True;"
```

> 開發環境啟動時不會檢查連線字串；沒設的話，第一次用到 Repository 才會拋「缺少 ConnectionStrings:… 設定」。

### 1.3 啟動

```bash
cd ReportCenter.Web
dotnet run
```

- 網址：`http://localhost:5276`（https：`https://localhost:7276`）
- `ASPNETCORE_ENVIRONMENT=Development`（`Properties/launchSettings.json`）
- `.claude/launch.json`、`.codex/environments/environment.toml` 也是同樣的啟動指令

### 1.4 開發環境的特殊行為

| 項目 | 開發環境 | 測試 / 正式 |
|------|---------|------------|
| 身分 | `DevWindowsAuthMiddleware` 依 `MockWindowsAuth` 模擬（預設 `PROSKIT\10255` 高先生 / 資訊部 109） | 登入頁（DataHubApi JWT + 本站 Cookie） |
| 首頁戰情 | `MockHomeDashboardRepository` 假資料 | SP `usp_Rpt_Home_YtdTarget` |
| 管理員 | `appsettings.Development.json` 的 `AdminUsers`（`10308`、`10255`） | `RC_CONFIG_PATH` 檔的 `AdminUsers` |
| 診斷頁 | `/_diag/windows-auth` 開啟 | 預設關閉 |
| 例外 | Developer Exception Page | `/Error` 頁 + log |
| 日誌 | Console | File + Seq |

**切換身分測試**：改 `appsettings.Development.json` 的 `MockWindowsAuth`（`UserName`、`EmployeeId`…）後重新啟動。例如：

- 測一般使用者：把 `EmployeeId` 改成不在 `AdminUsers` 內的員編 → 只會看到有授權的報表、看不到系統管理。
- 測無權限者：用一個沒有任何授權的員編 → 所有部門 0 筆。

### 1.5 本機測試登入頁

把 `MockWindowsAuth:UserName` 留空，就不會注入模擬身分，改走真正的登入頁。需要一個可以發 RS256 JWT 的 DataHubApi（本機 DataHubApi，或依合約運作的 mock），並把它的公鑰放進 User Secrets：

```bash
cd ReportCenter.Web
dotnet user-secrets set "DataHubAuth:PublicKeyPem" "$(cat dev-public.pem)"
dotnet run -- --urls=http://localhost:5276 --DataHubAuth:ApiBaseUrl=http://localhost:5299/api --MockWindowsAuth:UserName=
```

- 站台和 API 要用**相同的 scheme**（都 http 或都 https）。一個 https、一個 http 會被當成不同站，`dh_rt` Cookie 送不出去，就只能測帳密登入。
- 從 `localhost` 連測試區的 DataHubApi（`dhtest.prokits.com.tw`）也是不同站，同樣測不到免登入；免登入要部署到測試區後再測。

### 1.6 建置

```bash
cd ReportCenter.Web
dotnet build
```

`dotnet build`（含 `dotnet run`、`dotnet publish`）會先執行 csproj 的 `BuildTailwindCss` target，以 Tailwind standalone CLI 把 `Styles/input.css` 編譯為 `wwwroot/css/site.css`（已壓縮）。只有 `Styles/input.css`、`tailwind.config.js`、`Pages/**/*.cshtml`、`wwwroot/js/**/*.js` 有變動才會重新編譯。

**第一次建置前**先下載 CLI（約 40 MB，不進版控）：

```powershell
New-Item -ItemType Directory -Force tools\tailwindcss
Invoke-WebRequest https://github.com/tailwindlabs/tailwindcss/releases/download/v3.4.17/tailwindcss-windows-x64.exe -OutFile tools\tailwindcss\tailwindcss-windows-x64.exe
```

（在 `ReportCenter-App/` 目錄下執行。）CLI 不存在時建置會失敗，並顯示「找不到 Tailwind CLI」與下載網址；CLI 放在其他位置時，可以用 `dotnet build -p:TailwindCli=<完整路徑>` 指定。

- 新增 Tailwind class 只要寫在 `.cshtml` / `.js` 裡，build 時就會被掃描到；以字串組合、原始碼中沒有完整 class 名稱的（如分類色票），須加進 `tailwind.config.js` 的 `safelist`
- 共用的 component class（`.card`、`.badge`、`.page-container`、`.menu-item`）定義在 `Styles/input.css`
- 前端套件放在 `wwwroot/lib/<套件>/<版本>/`（Alpine 3.15.12、Lucide 1.25.0、Chart.js 4.5.1、HTMX 2.0.4），字型在 `wwwroot/lib/fonts/noto-sans-tc/`（Google Fonts 的 unicode-range 切片，約 5 MB，瀏覽器只下載頁面用到的切片）。全站不引用外部 CDN
- 繁→簡字典 `wwwroot/js/zh-t2s.js` 由 `python tools/gen-zh-t2s.py <TSCharacters.txt>` 產生（字典檔取自 OpenCC repo 的 `data/dictionary/`），勿手改；更新 OpenCC 版本時才需要重新產生

目前專案**沒有自動化測試專案**。

### 1.7 重拍使用手冊截圖

`/Admin/Help` 的截圖（`wwwroot/images/help/*.webp`）由 `tools/help-screenshots.py` 產生：以 Playwright 開本機 Chrome 拍 1600×956 畫面，橘色標註框依元素實際位置自動繪製。

```bash
pip install playwright pillow          # 用本機已安裝的 Chrome，不需 playwright install
cd ReportCenter.Web && dotnet run      # 另開視窗；目前模擬身分須為管理員
python tools/help-screenshots.py                      # 全部重拍
python tools/help-screenshots.py 03-catalog 04-edit-basic   # 只拍指定幾張
```

- 只做勾選、展開、切換頁籤，**不會儲存或指派**，不改動資料。
- 畫面用到的報表（ID 7）、人員（員編 10255）取自開發 DB，換環境時改腳本開頭的常數。
- 標註編號順序必須與 `Help.cshtml` 中 `Shot(...)` 的說明條數一致；增減說明時同步改腳本裡對應的標註清單。

## 2. 環境與設定檔

| 環境 | `ASPNETCORE_ENVIRONMENT` | 設定來源 |
|------|-------------------------|---------|
| Development | `Development` | `appsettings.json` + `appsettings.Development.json` + User Secrets |
| Staging | `Staging` | `appsettings.json` + `appsettings.Staging.json` + 外部機密檔 |
| Production | `Production`（未設定時的預設值） | `appsettings.json` + `appsettings.Production.json` + 外部機密檔 |

`web.config` 沒有設定 `ASPNETCORE_ENVIRONMENT`，因此 IIS 上預設就是 **Production**；若要架 Staging，需在 `web.config` 的 `<environmentVariables>` 或 IIS 設定中加上 `ASPNETCORE_ENVIRONMENT=Staging`。

### 2.1 外部機密檔

非開發環境由 `web.config` 的環境變數指定兩個 JSON 檔（後者覆蓋前者）：

| 環境變數 | 目前 `web.config` 的值 | 內容（範本） |
|----------|----------------------|-------------|
| `SHARED_INFRA_PATH` | `C:\CompanySecrets\shared-infra.Production.json` | `ConnectionStrings:PKSYS`、`Seq:ServerUrl`、`Seq:ApiKey` |
| `RC_CONFIG_PATH` | `C:\CompanySecrets\reportWebApp-Site.Production.json` | `ConnectionStrings:ReportCenter`、`AdminUsers` |

範本在 `ReportCenter.Web/docs/開發/*.template.json`（路徑與 `web.config` 一致為 `C:\CompanySecrets\`；若伺服器實際放在其他磁碟，請同步修改 `web.config`）。

- 環境變數有設但檔案不存在 → **啟動失敗**。
- 兩個連線字串任一缺少 → **啟動失敗**。
- 啟動失敗的原因會寫在 Bootstrap Logger（Console）；IIS 上要看可暫時把 `web.config` 的 `stdoutLogEnabled` 改成 `true`，輸出到 `logs\stdout*`。

## 3. IIS 部署

### 3.1 伺服器前置

1. 安裝 .NET 10 **ASP.NET Core Hosting Bundle**。
2. 站台驗證設定：**啟用匿名驗證、停用 Windows 驗證**。登入由程式處理（見 [內部站台登入規格](內部站台登入規格.md)）；Windows 驗證若開著，非網域電腦會一直跳 AD 帳密視窗。
   `web.config` 沒有包含這兩項設定（`<security><authentication>` 區段在 IIS 預設是鎖定的，寫進 `web.config` 反而會造成 HTTP 500.19），請在 IIS 管理員對站台設定。
   應用程式本身已設定 FallbackPolicy：未登入的請求一律導向登入頁或回 401，不會被放行。
3. 站台必須以 **`https://*.prokits.com.tw`** 網址開啟：登入 Cookie 設有 `Secure`；而且要和 DataHubApi 同站，才能沿用 PKPortal 的登入（免登入）。
4. 建立外部機密檔（§2.1），並確認 App Pool 身分有讀取權限。
   - `appsettings.{環境}.json` 的 `DataHubAuth:PublicKeyPem` 要填 DataHubApi 該環境的公鑰（向 DataHubApi 管理者索取，見 DataHubApi `docs/部署與設定.md`「JWT 金鑰對」）。沒填或格式錯誤 → **啟動失敗**。
   - 建立 `DataProtection:KeysPath` 指定的資料夾（正式 `C:\CompanySecrets\DataProtectionKeys\Production\ReportCenter`、測試 `…\DataProtectionKeys\Staging\ReportCenter`，與 HomeWebApp 同一層；各站台各用一個資料夾，不可共用），並給 App Pool 身分**讀寫**權限。沒設定 → **啟動失敗**；金鑰遺失 → 所有人被登出一次。
5. 資料庫：
   - App Pool 身分（若連線字串用 `Integrated Security`）需有 ReportCenter 讀寫、PKSYS 讀取、執行 `usp_Rpt_Home_YtdTarget` 的權限。
   - 新環境先執行 `db-ddl.sql`。
6. 站台目錄下 `logs\` 需讓 App Pool 身分可寫入（Serilog File Sink）。

### 3.2 發佈

```bash
cd ReportCenter.Web
dotnet publish -c Release -o ./publish
```

發佈時同樣會先編譯 `site.css`，所以建置機上要有 Tailwind CLI（見 1.6）；IIS 伺服器本身不需要。`Styles/`、`tailwind.config.js` 不會輸出到 `publish/`。

將 `publish/` 內容複製到 IIS 站台目錄（`web.config` 已隨專案輸出，`hostingModel="inprocess"`）。

> repo 中的 `.github/workflows/deploy.yml` 是早期前端版本遺留的 GitHub Pages（npm build）流程，**與目前的 .NET 專案無關**，不能用來部署。

### 3.3 部署後檢查清單

1. 用無痕視窗開首頁，會導到登入頁；登入後回到首頁，頂欄顯示的姓名 / 暱稱正確（代表 JWT 驗證 + PKSYS 查詢成功），公司別預設為使用者所屬區域。
2. 先在 PKPortal 登入，再開本站：不會出現帳密表單（Network 中 `/api/Auth/Refresh` 回 200）。按右上角登出後，PKPortal 重新整理也要重新登入。
3. 管理員帳號側欄出現「系統管理」，一般帳號沒有。
4. 首頁三張 KPI 卡有真實數字（代表 SP 可執行）。
5. 點一張報表後，到 `/Admin/Usage` 明細查得到這筆點擊。
6. `logs\rc-YYYYMMDD.log` 有寫入；有設 Seq 的話 Seq 上看得到事件。
7. 回收 App Pool 後重新整理，仍維持登入（代表 Data Protection 金鑰有存下來）。

### 3.4 身分問題排查

若出現「名字顯示成員編」「看不到報表」「管理員進不了管理頁」：

1. 在外部機密檔設定 `"WindowsAuthDebug": { "Enabled": true }`，回收 App Pool。
2. 開 `/_diag/windows-auth`，檢查：
   - `IsAuthenticated` 是否為 true、`AuthenticationType` 是否為 `Cookies`
   - 一直停在登入頁：看 log 的「登入 Token 驗證失敗：…」。`SecurityTokenSignatureKeyNotFoundException` 代表 `DataHubAuth:PublicKeyPem` 與 DataHubApi 的私鑰不是同一組
   - 正規化帳號是否等於員編
   - PKSYS 是否查得到（`PksysUserFound`、錯誤訊息）
   - `UserInfo.Id` 是否在 `AdminUsers` / 是否有授權
3. 排查完**務必關閉**診斷頁。

## 4. 日誌查詢

- 檔案：`{站台目錄}\logs\rc-YYYYMMDD.log`，保留 30 天。
- 每行格式：`時間 [等級] [來源類別] TraceId=… User=… 訊息`
- 使用者回報錯誤時，請對方提供錯誤頁上的 **TraceId**，用它搜尋 log / Seq。

## 5. 開發規範摘要

完整規範見 `CLAUDE.md`，重點：

- UI 文字、註解、commit message 使用繁體中文。
- 商業邏輯放 `Services/`，資料存取放 `Repositories/`，View 只負責呈現。
- 樣式用 Tailwind utility，互動用 Alpine；複雜 Alpine 邏輯寫成 `function xxxPage()` 放在 `@section Scripts`。
- 新增報表連結務必加上 `data-report-id`、`data-report-source`（否則不會記錄使用）。
- 新增任何「取得部門」的方法務必套用 `DepartmentDisplay` 白名單過濾。
- 新管理頁一律繼承 `AdminPageModel`。
- 所有 SQL 相容 SQL Server 2008 R2。
