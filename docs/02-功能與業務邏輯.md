# 02 — 功能與業務邏輯

本文依「使用者看到的功能」逐一說明：資料從哪來、怎麼算、有哪些判斷。規則的精簡條列見 [03-業務規則總表](03-業務規則總表.md)。

## 1. 全站共通

### 1.1 版面

每頁都由 `_Layout.cshtml` 組成：頂欄 `_TopNav` + 側欄 `_Sidebar` + 內容 + 全站搜尋 Dialog。

- **頂欄**：Logo、公司切換選單、搜尋按鈕（`⌘K` 提示）、使用者姓名與暱稱（`UserInfo.Name` / `NickName`）。
- **側欄**：
  - 「首頁」＋「部門」清單（目前公司別的部門，括號數字 = 該部門**你看得到的**報表數）
  - 「系統管理」區塊：**只有管理員看得到**（報表目錄管理 `/Admin`、使用分析、權限管理）
  - 「快捷存取 → 我的收藏」：收藏的報表，點擊直接開外部報表
- 手機版（< 1024px）側欄改為抽屜，公司切換也移到抽屜內。

### 1.2 公司別切換

- 公司清單目前寫死兩家：`tw` 台灣寶工（Region `TW`）、`sh` 上海寶工（Region `SH`）。
- 切換時前端寫入 cookie `companyId`（效期 1 年）並重新整理頁面。
- **目前公司別的判定**：cookie 有值且是合法公司 → 用 cookie；否則用使用者預設公司——依 PKSYS 所屬部門的 `Area`（`TW`→台灣寶工、`SH`→上海寶工，查無時台灣寶工）。全站統一由 `IReportService.GetCurrentCompanyId()` 判定。
- 公司別影響：
  - 側欄與部門頁顯示哪一區的部門（依 `DepartmentDisplay.Regions.{TW|SH}`）
  - 報表連結的 `dbs` 參數（見 §1.4）
  - 使用記錄的 `CompanyId` 欄位
- 公司別**不**影響：首頁年度戰情（固定三區都顯示）、權限（權限不分公司）。

### 1.3 「你看得到哪些報表」— 權限過濾

所有一般使用者的報表清單（部門頁、側欄數量與收藏、首頁釘選、全站搜尋）都經過 `SqlReportService` 同一套過濾：

1. 報表必須 `IsActive = 1`，且被指派到該部門（`ReportDepartment`）。
2. **管理員**（員工編號在 `AdminUsers`）：不再過濾，看得到全部啟用中報表。
3. **一般使用者**：只留下 `UserReportPermission` 中有自己員工編號的報表。
   沒有任何授權 → 每個部門都是 0 筆（**預設無權限**）。

授權清單每個請求只查一次 DB（快取在 `HttpContext.Items`）。

### 1.4 外部報表連結的組法

```
SSRS        → ReportBaseUrls:SSRS       + ReportCode
其他 (SmartQuery) → ReportBaseUrls:SmartQuery + ReportCode
若 UseCompanyParam = true → 再加上 ?dbs={目前公司別} 或 &dbs=…
```

- 一律 `target="_blank"` 新視窗開啟，本站不轉址、不代理。
- `UseCompanyParam` 讓同一張 SmartQuery 報表依台灣 / 上海切換資料庫。
- 連結一律由後端 `IReportService.BuildReportUrl()` 組好（部門頁、側欄收藏、首頁釘選、全站搜尋皆同），`dbs` 使用 §1.2 判定的公司別，不會是空值。

### 1.5 全站搜尋

- 開啟：頂欄搜尋按鈕或 `Ctrl/⌘ + K`。
- 索引：`_Layout` 在每次頁面載入時，把**目前公司別 × 你看得到的**所有報表組成索引注入前端。
- 比對：報表名稱、說明、部門名、分類名（不分大小寫、包含即符合），最多顯示 8 筆。
- 點選結果 → 記錄使用（來源 `search`）→ 新視窗開啟。

### 1.6 收藏（★）

- 在部門頁報表卡片上切換，呼叫 `POST /Api/Favorite?handler=Toggle&reportId=`。
- 存在 `UserFavorite (UserID, ReportID)`，**不分部門、不分公司**。
- **新增**收藏前會檢查：報表存在且啟用，且使用者有權限（管理員免授權）；不符合回 HTTP 403。**取消**收藏一律允許（即使已失去權限）。
- 顯示時一樣經過權限過濾：失去權限的收藏會自動從畫面消失（資料仍在）。
- 同一報表若指派給多個部門，側欄收藏清單會依 ReportID 去重。

### 1.7 使用記錄（點擊埋點）

報表連結元素帶 `data-report-id` 與 `data-report-source`，`site.js` 在 document 上監聽 `click` 與中鍵 `auxclick`，以 `navigator.sendBeacon` 背景送到 `POST /Api/Usage?handler=Track`，不影響開新視窗。

| 入口 | `source` |
|------|----------|
| 部門頁報表卡片 | `department` |
| 首頁快速存取（釘選） | `pin` |
| 側欄我的收藏 | `favorite` |
| 全站搜尋 | `search`（`go()` 內直接呼叫，因為是動態產生的 `<a>`） |

後端 `UsageService.TrackClick()`：

1. `reportId <= 0` 或取不到使用者 → 不記。
2. `source` 不在上表四種 → 存空字串。
3. 公司別依 §1.2 規則判定。
4. **30 秒防重複**：同一人同一報表 30 秒內已有記錄就不寫（SQL `IF NOT EXISTS … INSERT`）。前端也有同樣 30 秒節流，但後端才是權威。

這是**分析用途**的資料，允許少量遺漏（例如瀏覽器不支援 beacon 又關閉頁面），不能當稽核紀錄。

## 2. 首頁 `/` — 年度目標戰情

### 2.1 畫面組成

1. **控制列**：模式「銷售 / 接單」、區間「月結累計 / 即時累計」、區間說明 tooltip。
2. **三張 KPI 卡**（固定順序：外銷 → 台灣 → 中國）：區域名、幣別、累計達成率（大字）、年度目標、累計金額、去年同期比較（↑綠 / ↓紅 / 持平）。
3. **累計達成率走勢**：Chart.js 折線圖，X 軸 1 月 ~ 截止月，三條線；可切換成無障礙文字表格。
4. **快速存取**：使用者釘選的報表卡片 + 「管理釘選」Dialog。

### 2.2 參數與預設值

| 參數 | 值 | 說明 |
|------|----|------|
| Mode | `S` 銷售（預設值）/ `O` 接單 | 非法值一律當 `S` |
| CumulativeType | `M` 月結累計 / `R` 即時累計 | 非法值一律當 `M`；**首頁初次載入用 `R` 即時累計** |
| ReportYear | 傳 `NULL` | 由 SP 決定系統當年度；首頁不提供切換年度 |

切換模式或區間時，前端呼叫 `GET /Api/HomeDashboard?handler=Data&mode=&cumType=` 局部更新卡片與圖表；連續切換會中止前一個請求；失敗時保留上一次成功的資料並顯示「重新載入」。

### 2.3 資料來源與計算

- 正式 / 測試環境：ReportCenter DB 的 `dbo.usp_Rpt_Home_YtdTarget @Mode, @CumulativeType, @ReportYear`，回傳兩個結果集（原始碼與計算規則見 [04](04-資料庫.md)，`ReportCenter.Web/docs/開發/usp_Rpt_Home_YtdTarget.sql`）。
- 開發環境：`MockHomeDashboardRepository` 產生示意資料，**正式環境永遠不會顯示假資料**。
- **快取**：同一組「模式 + 區間」的結果全站共用快取——月結累計快取到當天結束、即時累計快取 5 分鐘。因此即時累計最多可能落後 5 分鐘；若需要立即看到最新數字（例如剛補登資料），回收 App Pool 即可清除快取。

| 欄位 | 定義 |
|------|------|
| 截止月 M | 月結累計 = 當月 − 1（統計至上月底，已結帳）；即時累計 = 當月（含本月未結帳數字） |
| 累計金額 A | 1 月 ~ M 月累計 |
| 年度目標 T | 全年目標 |
| 累計達成率 | A ÷ T（可大於 100%） |
| 去年同期成長率 | (A − 去年同期 L) ÷ \|L\|，可為負 |
| 走勢點 | 第 m 月累計 ÷ **全年目標**（分母固定為全年，不是月目標） |

- 三區各用原幣：外銷 USD、台灣 NTD、中國 RMB。**跨區只能比百分比，金額不能相加。**
- 顯示格式：百分比 ×100 四捨五入到整數；金額四捨五入加千分位；走勢點保留一位小數。
- 1 月選「月結累計」時 M = 0，走勢沒有資料，顯示「目前沒有可顯示的趨勢資料」。
- 首頁戰情**不經權限過濾、不分公司別**，所有登入者看到同一份數字。

### 2.4 快速存取（釘選）

- 釘選存在 `UserPin (UserID, ReportID, SortOrder, CreatedDate)`；新增時 `SortOrder = 目前最大值 + 1`，依此排序顯示（目前沒有拖曳排序 UI）。
- 首頁只顯示「仍啟用 ＋ 有權限 ＋ 屬於目前公司別某個顯示部門」的釘選。
- 「管理釘選」Dialog：
  - 範圍切換「已釘選（預設）」/「全部報表」，並可依名稱 / 部門 / 分類搜尋
  - 「全部報表」= 目前公司別 × 你看得到的報表
  - 釘選 / 取消呼叫 `POST /Api/Pin?handler=Toggle&reportId=`；新增釘選的權限檢查規則同收藏（§1.6）

## 3. 部門報表 `/Department?dept={DeptID}`

- 部門必須是目前公司別、`DepartmentDisplay` 白名單內、且 PKSYS `User_Dept.Display='Y'` 的部門。
- **網址的部門不屬於目前公司**（例如切換公司後重新整理）→ 自動導向目前公司的第一個部門；連一個部門都沒有 → 顯示「未知部門」。
- 報表清單 = 該部門啟用中、你有權限的報表（§1.3）。
- 前端功能：
  - 分類 Tab：「全部」+ 該部門出現過的分類（依名稱排序），每個 Tab 顯示符合搜尋條件的筆數；網址可帶 `&cat=分類名` 預選 Tab
  - 搜尋：名稱、說明、分類
  - 排序：**固定依更新日新到舊**（更新日 = `ModifyDate`，沒有就 `CreateDate`，格式 `yyyy/MM/dd`）
  - 收藏切換、點擊開外部報表（記錄 `department`）
- 分類徽章配色：依分類在該部門的序位輪流套 5 種顏色（`CategoryPalette.BadgeByIndex`），確保同頁相鄰分類顏色不同。

## 4. 系統管理（僅管理員）

### 4.1 存取控制

所有 `Pages/Admin/*` 都繼承 `AdminPageModel`，在**每個 handler 執行前**（GET、POST、AJAX 皆然）檢查 `AdminUsers` 白名單：

- 非管理員的 GET → 顯示「權限不足」頁（HTTP 200，內容換成 `_AccessDenied`）
- 非管理員的 POST → HTTP 403 + `{ success:false, message:"權限不足" }`

側欄的「系統管理」區塊也只對管理員顯示，但真正的把關在 `AdminPageModel`。

### 4.2 管理總覽 `/Admin`

| 區塊 | 內容 / 計算 |
|------|------------|
| KPI | 報表總數（含停用）、啟用數 / 停用數、各工具類型數量（內部 / SmartQuery / SSRS） |
| 部門使用矩陣 | 台灣、上海兩欄；每個部門列出被指派的**啟用中**報表。只列 `DepartmentDisplay` 內的部門，沒有任何報表的部門不出現 |
| 未指派部門的報表（孤立報表） | `ReportDepartment` 沒有任何列的報表（含停用）。這些報表不會出現在任何使用者畫面 |
| 冷門報表 | 啟用中且近 90 日 0 次點擊，依最後使用時間舊到新（從未使用者在最前），預覽 6 筆，完整清單在 `/Admin/Usage` |

### 4.3 報表目錄管理 `/Admin/Catalog`

**清單**：全部報表（含停用），依更新日新到舊；前端可依工具類型、啟停狀態、資料夾、關鍵字（名稱 / 來源 / 路徑）篩選。篩選條件同步到網址（`q` / `type` / `status` / `folder`，重新整理不會遺失）；儲存、刪除整頁重載前會把篩選與捲動位置暫存在 `sessionStorage`，重載後還原，並捲動、標亮剛儲存的那一列。

> 不做分頁：報表約數十份，前端全載篩選即可；分頁反而會讓「操作後回到原列」與瀏覽器 Ctrl+F 失效。數量成長到數百份再評估。

**清單欄位**：報表（名稱 + 工具類型 / 資料夾 / 資料來源）、部門選單（列前兩個名稱，超過以「等 N 個」開明細）、分類（寬螢幕）、近 30 日（寬螢幕）、狀態開關、編輯。更新日期與 ID 移到編輯視窗底部；**刪除只在編輯視窗內**，不在每一列常駐。寬度 < 768px 改為卡片清單（44px 觸控目標），篩選列不黏頂。

**「近 30 日」欄**：有使用顯示「N 次」（滑過看最後使用日，點擊下鑽 `/Admin/Usage?reportId=`）；0 次顯示「未使用」，啟用中者以警示色呈現。停用確認視窗也會帶出這項數字。

**新增 / 編輯 Modal**（三個 Tab）：

| 欄位 | DB 欄位 | 說明 |
|------|---------|------|
| 報表名稱 | `ReportName` | |
| 工具類型 | `ReportTool` | 選項只有 `SmartQuery`、`SSRS`（DB 預設值 `Internal` 已不再提供） |
| 報表資料夾 | `ReportPath` | 存的是**資料夾標籤字串**，選項來自 `ReportFolder` 列舉：`00-經營層報表`、`01-總經理室`、`20-外業報表`、`30-內業報表`、`50-上海業務`、`80-會計報表` |
| 報表代碼 | `ReportCode` | 接在 BaseUrl 後面的路徑 / 參數 |
| 資料來源 | `SourceName` | SP / 函數名稱（文件用途） |
| 分類 | `CategoryID` | 可「未分類」 |
| 說明 | `Remarks` | 顯示在部門頁卡片上 |
| 帶公司別參數 | `UseCompanyParam` | 勾選後連結自動加 `dbs={companyId}` |
| 啟用 | `IsActive` | |
| 部門指派 | `ReportDepartment` | 台灣 / 上海部門勾選（只列白名單部門），存 `DeptID` + 當下的 `DeptName`（顯示時以 PKSYS 目前名稱為準，見 03 規則 E4） |
| 相依物件 | `ReportDependency` | 這張報表依賴的 SP / View / Table，有自動完成 |

**儲存驗證**（前端 + 後端 `CatalogModel.OnPostSave`）：報表名稱、報表代碼必填；工具類型只能是 `SmartQuery` / `SSRS`。前端不符合時標紅欄位、切回「基本設定」並聚焦；後端不符合時不寫入，導回 `?msg=invalid` 顯示錯誤提示。

**Modal 防呆**：有未儲存變更時，點背景、按 Esc、取消、右上 X 都會先確認是否放棄；`Ctrl + S` 可直接儲存。

**儲存規則**（`SqlCatalogRepository.SaveCatalogItem`，單一交易）：

- 新增：`CreateDate = ModifyDate = GETDATE()`
- 更新：`ModifyDate = GETDATE()`
- 部門指派、相依物件都採「**先全刪再重建**」

**啟停用**：直接翻轉 `IsActive`（會更新 `ModifyDate`）。前端以 AJAX 呼叫 `?handler=Toggle`（回傳 JSON），就地更新該列，不重新載入頁面。停用後報表從所有使用者畫面消失，但權限、收藏、釘選、使用記錄都保留，重新啟用即恢復。

**刪除**：硬刪除。刪除 `ReportCatalog` 後，權限、收藏、釘選、使用記錄會因 FK `ON DELETE CASCADE` 一併清掉。**要汰除報表請優先用「停用」**，以保留歷史使用數據。

儲存、刪除的結果以 `?msg=saved|deleted`（儲存另帶 `focus={ReportID}`）帶回頁面顯示 Toast。

### 4.4 使用分析 `/Admin/Usage`

**Tab 1：分析總覽**

| 指標 | 定義 |
|------|------|
| 近 30 日總點擊 | 期間內 `ReportUsageLog` 筆數 |
| 活躍使用者 | 期間內不重複員工編號數 |
| 有被使用的報表 | 期間內有點擊的報表數 / 啟用中報表總數 |
| 冷門報表數 | 啟用中且 90 日內 0 次 |
| 每日點擊趨勢 | 近 30 日逐日點擊數，沒有點擊的日子補 0 |
| 熱門 Top 10 | 可切換近 30 日 / 近 90 日，依點擊數多到少（同數依最後使用時間新到舊），顯示點擊數、使用人數 |
| 冷門清單 | 同 §4.2，不限筆數 |

「近 N 日」= **含今天往回 N 天**（今天 00:00 往前推 N−1 天起算）。

> 熱門排行包含已停用的報表（只要期間內有點擊）；冷門清單只看啟用中報表。

**Tab 2：明細查詢**（伺服器端篩選 + 分頁）

- 條件：報表（下拉含停用報表）、使用者關鍵字、起訖日（迄日含當天）。
- 使用者關鍵字先到 PKSYS 以員編或姓名模糊比對，取得員編清單後再查記錄；比對不到任何人直接回傳空結果。
- 每頁 20 筆（上限 100），依點擊時間新到舊；分頁用 `ROW_NUMBER()`（相容 SQL 2008 R2）。
- 姓名 / 部門由 PKSYS 補上（只查本頁出現的員編）；查不到（離職等）就顯示員編。
- 網址帶 `reportId` 時自動切到明細 Tab（供目錄管理下鑽）。

### 4.5 權限管理 `/Admin/Permission`

**原則：以「人」為單位授權，沒有部門權限、沒有角色。**

**模式 A：功能 → 多人（批次）**

- 左：報表樹（分類 → 報表），只含**啟用中**報表；分類節點只列啟用中分類。沒有分類、或所屬分類已停用的報表放在「未分類」，確保每張啟用中報表都能被授權。
- 右：人員樹（PKSYS 部門 → 人員），只含 `Display='Y'` 的部門與在職人員；**不受 `DepartmentDisplay` 白名單限制**，所有部門都列。
- 勾選後送出，對「每個人 × 每張報表」做授權；已存在的組合略過（冪等），回報新增數 / 略過數。以單一集合式 INSERT 完成（人數超過約 1000 時自動分批），整批在同一交易中；已不存在的報表會被略過、計入略過數。

**模式 B：單一人 → 功能（個人）**

- 搜尋人員（員編或姓名模糊比對）→ 列出該人目前所有權限（含停用報表）。
- 可單筆撤銷（確認後直接刪除）或批次新增。

`GrantedBy` 記錄操作的管理員員編，`GrantedDate` 由 DB 預設。

> 管理員本身不需要授權即可看到所有報表，所以授權資料只對一般使用者有意義。

## 5. 診斷與錯誤頁

### 5.1 `/_diag/windows-auth`

- 只有 `WindowsAuthDebug:Enabled = true` 才存在，否則 404。
- 非開發環境需已通過驗證，否則觸發 Windows 驗證挑戰。
- 顯示：驗證狀態、`Identity.Name`、正規化帳號、所有 Claims、PKSYS 查詢帳號與結果、`UserInfo` 每個欄位（含預設公司別）的值與**來源**（Claim / PKSYS / Fallback）、TraceId、IP、`X-Forwarded-For`、User-Agent、主機、環境、伺服器時間。
- 用途：正式環境「登入後名字不對、部門不對、看不到報表」時，確認身分解析到哪一步出問題。**用完請關閉**。

### 5.2 `/Error`

非開發環境的未處理例外導向此頁，顯示 TraceId、原始路徑、例外類型名稱，方便對照 log。
