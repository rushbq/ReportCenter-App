# 03 — 業務規則總表

每條規則附上**實作位置**，修改規則時請同步修改程式與本表。路徑皆相對於 `ReportCenter.Web/`。

## A. 身分與角色

| # | 規則 | 實作位置 |
|---|------|---------|
| A1 | 使用者鍵 = 員工編號。登入 Cookie 的 `Name` 即工號（帶網域如 `PROSKIT\10255` 時去掉網域；若有 `EmployeeId` claim 則優先用它） | `Services/SqlReportService.cs` `BuildCurrentUserDebugInfo` |
| A2 | 姓名、部門、暱稱以 claim 優先，其次 PKSYS `User_Profile`（`Display='Y'`），都沒有則退回帳號 | 同上 `Resolve*` 方法 |
| A3 | PKSYS 查詢失敗不中斷請求，只寫 Error log | 同上 |
| A4 | 全站預設須登入（FallbackPolicy，所有環境）。未登入時一般換頁 302 到 `/Account/Login`，fetch / sendBeacon 等請求回 401；萬一未登入請求進入，視為空使用者（非管理員、無任何權限），絕不退回固定使用者 | `Program.cs`、`SqlReportService.GetCurrentUser` |
| A4-1 | 登入由 DataHubApi 負責（與 PKPortal 共用）：登入頁先用 DataHubApi 的 Refresh Token 自動登入，失敗才顯示帳密表單；帳密直接送 DataHubApi，不經本站伺服器。本站只接受以 DataHubApi 公鑰驗證通過（RS256、Issuer、Audience、有效期限）的 JWT | `Pages/Account/Login.cshtml(.cs)`、`Services/DataHubTokenValidator.cs` |
| A4-2 | 本站 Cookie `rc_auth` 有效 8 小時，有使用就延長；過期時自動走一次登入流程，使用者不用重新輸入帳密（只要 DataHubApi 的 Refresh Token 仍有效，90 天） | `Program.cs`、`wwwroot/js/site.js` |
| A4-3 | 登出會同時撤銷 DataHubApi 的 Refresh Token，PKPortal 等共用登入的站台一起登出；登出後的登入頁不做自動登入 | `wwwroot/js/site.js` `rcLogout`、`Pages/Account/Logout.cshtml.cs` |
| A4-4 | 登入後只能導回站內網址（`returnUrl` 非站內一律改回 `/`） | `Pages/Account/Login.cshtml.cs` `SafeReturnUrl` |
| A5 | 管理員 = 員編在 `AdminUsers` 設定陣列中（不分大小寫）；沒有其他角色 | `Services/PermissionService.cs` `IsAdmin`；`SqlReportService` 建構子 |
| A6 | 所有 `/Admin/*` 的 GET / POST handler 一律先檢查管理員；GET 顯示權限不足頁、POST 回 403 JSON | `Pages/Admin/AdminPageModel.cs` |
| A7 | 側欄「系統管理」只對管理員顯示（僅顯示層，非把關） | `Pages/Shared/_Sidebar.cshtml` |

## B. 報表可見性（權限）

| # | 規則 | 實作位置 |
|---|------|---------|
| B1 | 授權以「人 × 報表」為單位，沒有部門權限、沒有角色權限 | `UserReportPermission` 表 |
| B2 | **預設無權限**：一般使用者沒有授權就看不到任何報表 | `SqlReportService.GetAuthorizedReportIdSet` |
| B3 | **管理員不受權限過濾**，看得到所有啟用中報表 | 同上（回傳 `null` 代表不過濾） |
| B4 | 使用者畫面只顯示 `IsActive = 1` 的報表 | `SqlCatalogRepository.GetActiveReportsByDepartment`、`GetUserPins` |
| B5 | 報表必須指派到某個部門才會出現在使用者畫面；未指派 = 孤立報表 | `ReportDepartment` JOIN；`CatalogService.GetAdminStats` |
| B6 | 部門報表數、部門頁、收藏、釘選、全站搜尋都套用 B2~B5 同一套過濾 | `SqlReportService.GetDepartments / GetReports / GetUserFavorites / GetUserPins` |
| B7 | 收藏、釘選資料不因失去權限而刪除，只是不顯示 | 同上 |
| B8 | 授權是冪等的：重複授權同一組合會略過，不報錯；輸入的員編（忽略大小寫）與報表先去重，不存在的報表略過；回傳實際新增筆數 | `SqlPermissionRepository.GrantPermissions`（集合式 `INSERT … SELECT … WHERE NOT EXISTS`）＋ UQ 約束 |
| B9 | 授權記錄授權者員編 `GrantedBy` 與時間 `GrantedDate` | 同上 |
| B10 | 新增收藏 / 釘選前檢查：報表存在且啟用、使用者有權限（管理員免授權），否則 403；取消一律允許 | `SqlReportService.ToggleFavorite / TogglePin / CanAccessReport` |
| B11 | 權限管理報表樹：每張啟用中報表都必須可被授權；沒有分類或分類已停用者歸入「未分類」 | `PermissionService.GetReportTree` |

## C. 部門與公司別

| # | 規則 | 實作位置 |
|---|------|---------|
| C1 | **全域規則**：任何 Service 取得「要顯示給使用者的部門」時，都必須依 `appsettings.json` → `DepartmentDisplay.Regions` 白名單過濾 | `SqlReportService.GetDepartments`、`CatalogService.BuildDeptUsagesForRegion`、`CatalogService.GetCatalogDepartments` |
| C2 | 部門還必須在 PKSYS `User_Dept` 中 `Display='Y'` 且 `Area` 相符 | `SqlPksysRepository.GetCatalogDepartments` |
| C3 | 側欄部門順序 = 白名單設定順序；部門名稱取自 PKSYS | `SqlReportService.GetDepartments` |
| C4 | 新增 / 移除顯示部門只要改 `DepartmentDisplay` 設定，不需改程式 | `appsettings.json` |
| C5 | 例外：權限管理的人員樹列出**所有** PKSYS 顯示部門，不套白名單（要能授權給任何人） | `PermissionService.GetDeptUserTree` |
| C6 | 公司別 = cookie `companyId`（需為合法公司）▸ 使用者預設公司（PKSYS 部門 `Area`：TW→`tw`、SH→`sh`，查無→`tw`）；全站只由一個方法判定 | `SqlReportService.GetCurrentCompanyId`、`ResolveCompanyId` |
| C7 | 公司 → 區域：`tw`→`TW`、`sh`→`SH`；決定顯示哪一區部門 | `MockReportService.GetCompanies` |
| C8 | 網址中的部門不屬於目前公司時，導向目前公司第一個部門 | `Pages/Department.cshtml.cs` |
| C9 | 權限、收藏、釘選、首頁戰情都**不分公司別** | — |
| C10 | 部門代碼必須是數字（`ReportDepartment.DeptID` 為 INT）：`DepartmentDisplay` 有非數字 DeptID 時**啟動即失敗**；執行中遇到非數字代碼則記 Warning 並視為沒有報表 | `Program.cs`（`ValidateOnStart`）、`SqlReportService.GetReports` |

## E. 報表目錄維護

| # | 規則 | 實作位置 |
|---|------|---------|

## F. 使用記錄與分析

| # | 規則 | 實作位置 |
|---|------|---------|
| F1 | 只記錄四種入口：`department`、`pin`、`favorite`、`search`；其他來源值存空字串 | `UsageService.ValidSources` |
| F2 | 新增報表連結時必須加 `data-report-id` 與 `data-report-source`，否則不會被記錄 | `wwwroot/js/site.js` |
| F3 | 同一人同一報表 **30 秒**內只記一次；後端為權威，前端節流只是省請求 | `UsageService.DedupeSeconds`、`SqlUsageRepository.TryInsert`、`site.js` |
| F4 | 使用者身分由後端從驗證資訊取得，前端不傳 | `UsageService.TrackClick` |

| F8 | 近期統計 = 30 日；冷門判定 = **啟用中且 90 日內 0 次** | `UsageService.RecentDays / ColdDays` |

| F10 | 熱門排序：點擊數多到少，同數依最後使用時間新到舊；取前 10 | `SqlUsageRepository.GetReportSummaries`、`UsageService` |
| F11 | 明細查詢在伺服器端分頁，每頁 20 筆（1~100）；迄日含當天 | `UsageService.GetLogs` |

## H. 技術約束（必守）

| # | 規則 | 說明 |
|---|------|------|
| H1 | 所有 SQL 必須相容 **SQL Server 2008 R2（compatibility level 100）** | 禁用 `OFFSET/FETCH`、`IIF`、`CHOOSE`、`CONCAT`、`TRY_CAST`、`TRY_CONVERT`、`FORMAT`、`DATEFROMPARTS`、`EOMONTH`、`LEAD`、`LAG`、`THROW`、`SEQUENCE`。本機 SQL 版本較新，**跑得動不代表正式能跑** |
| H2 | 未預期例外一定要留下可查的 log（含 TraceId、路徑、使用者、SQL 錯誤資訊）；`catch` 不可吞例外 | `UnhandledExceptionLoggingMiddleware` |
| H3 | 前端不使用 npm，也**不引用任何外部 CDN**：套件與字型以固定版本放在 `wwwroot/lib/`，Tailwind 於 `dotnet build` 時由 standalone CLI 預先編譯成 `wwwroot/css/site.css`（勿手改）；繁簡字典見 I2 | `_Layout.cshtml`、`tailwind.config.js`、`docs/05` §1.6 |
| H4 | `<script>` 內注入的資料用 `JsonSerializer` + `UnsafeRelaxedJsonEscaping`，避免中文亂碼或被轉成 `\uXXXX` | 各 `.cshtml` |
| H5 | 分類配色前後端需一致（`site.js` `catBadge` 與 `Helpers/CategoryPalette.cs` 使用同一組 5 色） | — |
