# 01 — 系統架構

## 1. 全貌

```
 瀏覽器 (任何電腦；與 PKPortal 共用 DataHubApi 登入)
   │  本站 Cookie rc_auth（登入頁以 DataHubApi 的 JWT 換得，見 docs/內部站台登入規格.md）
   ▼
 IIS（只開匿名驗證）── ASP.NET Core Module (in-process)
   │
   ▼
 ReportCenter.Web (Razor Pages)
   ├─ Pages/            畫面 + 頁面邏輯 (PageModel)
   ├─ Services/         商業邏輯 (BLL)
   ├─ Repositories/     資料存取 (DAL, Dapper)
   │     ├──► SQL Server: ReportCenter  (報表目錄、權限、收藏、釘選、使用記錄、首頁戰情 SP)
   │     └──► SQL Server: PKSYS         (部門 User_Dept、人員 User_Profile，唯讀)
   └─ wwwroot/          site.js / site.css (Tailwind 編譯產物) / zh-t2s.js / 圖片
                         lib/：Alpine、Chart.js、HTMX、Lucide、Noto Sans TC（全部自架，不引用外部 CDN）

 使用者點報表 ──► 新視窗直接開 SmartQuery / SSRS（不經本站轉址）
               └► 背景 sendBeacon 到 /Api/Usage 記錄點擊
```

## 3. 分層與相依

三層式：**Page → Service → Repository**，全部以介面透過 DI 注入（皆為 `Scoped`）。

| 層 | 介面 | 實作 | 職責 |
|----|------|------|------|
| BLL | `IReportService` | `SqlReportService` | 目前使用者解析、公司清單、部門清單、報表清單（含權限過濾）、收藏、釘選 |
| BLL | `ICatalogService` | `CatalogService` | 報表目錄 CRUD、管理總覽統計、分類、部門指派選項 |
| BLL | `IPermissionService` | `PermissionService` | 授權/撤銷、管理員判定、權限頁樹狀資料 |
| BLL | `IUsageService` | `UsageService` | 點擊記錄（防重複）、使用分析統計 |
| BLL | `IHomeDashboardService` | `HomeDashboardService` | 首頁戰情參數正規化、組裝 ViewModel |
| BLL | `IDataHubTokenValidator` | `DataHubTokenValidator`（Singleton） | 以 DataHubApi 公鑰驗證登入 JWT，取出工號 |
| DAL | `ICatalogRepository` | `SqlCatalogRepository` | ReportCenter：目錄、分類、部門指派、相依物件、收藏、釘選 |
| DAL | `IPermissionRepository` | `SqlPermissionRepository` | ReportCenter：`UserReportPermission` |
| DAL | `IUsageRepository` | `SqlUsageRepository` | ReportCenter：`ReportUsageLog` |
| DAL | `IHomeDashboardRepository` | Dev：`MockHomeDashboardRepository`<br>其他：`SqlHomeDashboardRepository` | 首頁戰情（SP `usp_Rpt_Home_YtdTarget`） |
| DAL | `IPksysRepository` | `SqlPksysRepository` | PKSYS：`User_Dept`、`User_Profile` |

特殊註冊：`SqlReportService` 同時以**具體型別**與 `IReportService` 註冊（同一個 Scoped 實例），因為診斷頁 `/_diag/windows-auth` 需要呼叫介面上沒有的 `GetCurrentUserDebugInfo()`。

`MockReportService` 不是透過 DI 使用，而是被 `SqlReportService` 內部 `new` 出來，提供：

- 公司清單（目前寫死：`tw` 台灣寶工 / `sh` 上海寶工）
- 保留給未來「內部報表」的舊 Mock 資料（KPI、圖表、明細列），目前畫面未使用

## 4. HTTP Pipeline（`Program.cs`）

順序如下：

1. 例外處理：Development → `DeveloperExceptionPage`；其他 → `/Error`
2. `UseHttpsRedirection`
3. `UseSerilogRequestLogging`（每個請求一筆，見 §7）
4. `UseRouting`
5. `UseAuthentication()`（Cookie `rc_auth`）
6. （僅 Development）`DevWindowsAuthMiddleware`：未登入且設定了 `MockWindowsAuth:UserName` 時注入模擬身分
7. `UseAuthorization`
8. `UnhandledExceptionLoggingMiddleware`（記錄後重新拋出）
9. `MapStaticAssets().AllowAnonymous()` + `MapRazorPages`

非 Development 環境啟動時會檢查 `ConnectionStrings:ReportCenter`、`ConnectionStrings:PKSYS`、`DataProtection:KeysPath` 都有值，`DataHubAuth`（https 網址、可解析的公鑰）也必須正確，缺少就直接啟動失敗（錯誤訊息會寫進 Bootstrap Logger）。

> 所有環境都設定了 `FallbackPolicy = 需已登入`（fail-closed）。未登入時，一般換頁 302 到 `/Account/Login`；fetch、sendBeacon 等請求（`Sec-Fetch-Mode` 不是 `navigate`）回 **401**，由 `site.js` 的 fetch 包裝函式重新整理頁面，走一次自動登入。登入頁、登出、錯誤頁、靜態檔允許匿名。完整流程見 [內部站台登入規格](內部站台登入規格.md)。

## 5. 身分解析流程

`SqlReportService.GetCurrentUser()`，每個請求只算一次（快取在 `HttpContext.Items`）：

```
HttpContext.User
  ├─ 未通過驗證 ──► 空使用者 (Id = "")：非管理員、沒有任何報表權限
  │                 （正式環境有 FallbackPolicy，實際上進不到這裡）
  └─ 已驗證
       Identity.Name = "10255"（登入 Cookie 存的就是工號；開發模擬身分為 "PROSKIT\10255"，會去掉網域）
       查詢帳號 = Claim[EmployeeId] 有值就用它，否則用 "10255"
       └─► PKSYS.User_Profile (Display='Y' AND Account_Name=查詢帳號)
       組出 UserInfo：
         Id       = Claim EmployeeId ▸ PKSYS Account_Name ▸ 帳號去網域
         Name     = Claim DisplayName ▸ PKSYS Display_Name ▸ 帳號去網域
         DeptId   = Claim DepartmentId ▸ PKSYS DeptID
         DeptName = Claim Department ▸ PKSYS DeptName
         NickName = PKSYS NickName
         CompanyId = PKSYS 部門的 Area (TW→tw / SH→sh)，查無時 "tw"
```

- 正式環境的登入 Cookie 只有 `Name` claim（工號），所以實際上姓名、部門都來自 PKSYS。
- 開發環境的 `DevWindowsAuthMiddleware` 會塞入完整 claims（`appsettings.Development.json` → `MockWindowsAuth`）。
- PKSYS 查詢失敗只記 Error log，不中斷；欄位會退回帳號。

**員工編號（`UserInfo.Id`）是全系統的使用者鍵**：權限、收藏、釘選、使用記錄、管理員白名單都用它。

### 5.1 目前公司別與報表連結（單一來源）

- `IReportService.GetCurrentCompanyId()`：cookie `companyId` 為合法公司才採用，否則用 `UserInfo.CompanyId`。頂欄、側欄、部門清單、使用記錄全部呼叫它。
- `IReportService.BuildReportUrl(report)`：`BaseUrl + ReportCode`，`UseCompanyParam` 時附加 `dbs={目前公司別}`。部門頁、側欄收藏、首頁釘選、全站搜尋都由後端呼叫它組好連結再交給前端，**前端不自行拼接網址**。

### 5.2 每請求快取

`SqlReportService` 以 `HttpContext.Items` 快取目前使用者、授權報表清單、部門清單、各部門報表清單。一次頁面載入中側欄、搜尋索引、頁面本身會重複取用，快取後每個部門只查一次 DB。

### 5.3 跨請求快取（首頁戰情）

`HomeDashboardService` 以 `IMemoryCache` 快取首頁戰情結果（`Program.cs` 註冊 `AddMemoryCache()`），key = `HomeYtd:{Mode}:{CumulativeType}:{yyyyMMdd}`：

| 區間 | 快取到 |
|------|-------|
| 月結累計 (M) | 當天結束（已結帳，當天不會變） |
| 即時累計 (R) | 5 分鐘（`RealtimeCacheMinutes`） |

結果不分使用者，全站共用；最多 4 份。快取未命中時寫一筆 Information log（含 SP 耗時），可用來觀察快取效果。快取在記憶體中，App Pool 回收即清空；多台伺服器時各台各自快取。

## 6. 設定與機密

### 6.1 載入順序（後者覆蓋前者）

1. `appsettings.json`
2. `appsettings.{Environment}.json`
3. （開發）User Secrets
4. （非開發）`SHARED_INFRA_PATH` 指向的 JSON — 同台伺服器各站共用（如 PKSYS 連線、Seq）
5. （非開發）`RC_CONFIG_PATH` 指向的 JSON — 本站專用（如 ReportCenter 連線、AdminUsers）
6. 環境變數 / 命令列（ASP.NET Core 預設）

環境變數有設、但檔案不存在 → 啟動失敗（`FileNotFoundException`）；環境變數沒設 → 直接略過。

### 6.2 設定項一覽

| 區段 | 型別 / 位置 | 說明 |
|------|------------|------|
| `Site:Title` | `SiteSettings` | 瀏覽器標題，預設「報表中心入口網站」 |
| `ReportBaseUrls:SmartQuery` / `:SSRS` | `ReportBaseUrlSettings` | 外部報表網址前綴，報表連結 = 前綴 + `ReportCode` |
| `DepartmentDisplay:Regions:{TW\|SH}:Depts[]` | `DepartmentDisplaySettings` | 各公司別要顯示的部門白名單（`DeptID` + Lucide `Icon`），**順序即側欄順序** |
| `AdminUsers` | `string[]`（直接讀 `IConfiguration`） | 管理員員工編號白名單（不分大小寫）。`appsettings.json` 沒有此項，開發在 `appsettings.Development.json`，正式在 `RC_CONFIG_PATH` 檔 |
| `WindowsAuthDebug:Enabled` | `WindowsAuthDebugSettings` | 是否開放 `/_diag/windows-auth`，預設 `false`，開發環境 `true` |
| `MockWindowsAuth` | `MockWindowsAuthSettings` | 僅開發環境：模擬的使用者；`UserName` 留空就改走真正的登入頁 |
| `DataHubAuth:ApiBaseUrl` | `DataHubAuthSettings` | DataHubApi 的 API 根網址（含 `/api`）。正式 `https://datahubapi.prokits.com.tw/api`、測試 `https://dhtest.prokits.com.tw/api` |
| `DataHubAuth:PublicKeyPem` | `DataHubAuthSettings` | DataHubApi 的 RS256 公鑰（不是機密），放 `appsettings.{環境}.json`；開發放 User Secrets |
| `DataHubAuth:Issuer` / `:Audience` / `:CookieHours` | `DataHubAuthSettings` | 預設 `DataHubApi` / `PKPortal` / 8 小時 |
| `DataProtection:KeysPath` | — | Cookie 加密金鑰資料夾（非開發環境必填），見 [05 §3.1](05-開發與部署.md) |
| `ConnectionStrings:ReportCenter` / `:PKSYS` | — | 兩個資料庫連線 |
| `Seq:ServerUrl` / `:ApiKey` | — | 有填 `ServerUrl` 才啟用 Seq |
| `Serilog:MinimumLevel` | — | 基底等級（環境別會在程式中再覆寫） |

## 7. 日誌與觀測性（Serilog）

| 環境 | Sink | 最低等級 |
|------|------|---------|
| Development | Console（精簡格式） | Debug（Microsoft = Information，AspNetCore = Warning） |
| Staging / Production | File `logs/rc-YYYYMMDD.log`（每日滾動、保留 30 天、單檔 50 MB）＋ Seq（選配） | Information（Microsoft / AspNetCore / Dapper = Warning） |

- 所有事件帶 `Application`、`Environment`、`MachineName`。
- Request log 帶 `TraceId`、`UserName`、`ClientIp`；等級規則：靜態資源 → Verbose（等於不記）、例外或 5xx → Error、4xx → Warning、超過 3 秒 → Warning。
- 未處理例外由 `UnhandledExceptionLoggingMiddleware` 記錄 `TraceId`、`RequestPath`、`HttpMethod`、`UserName`、`QueryString`、`ClientIp`；`SqlException` 另記 `Number`、`Procedure`、`LineNumber`、`State`。
- 錯誤頁 `/Error` 會顯示 `TraceId`，使用者回報時可拿它到 log / Seq 查。

## 8. 前端架構

- **不用 npm / webpack，也不引用外部 CDN**：套件與字型以固定版本放在 `wwwroot/lib/`；Tailwind 在 `dotnet build` 時由 standalone CLI 把 `Styles/input.css` 編譯成 `wwwroot/css/site.css`，色彩 token 設定在 `tailwind.config.js`（見 `docs/05` §1.6）。
- 頁面資料由 PageModel 序列化成 JSON 注入 `<script>`，Alpine 元件（`function xxxPage()`）在前端做篩選、排序、切換。
- 少數互動用 `fetch` 呼叫 `Pages/Api/*` 的 handler（收藏、釘選、首頁戰情）。
- `site.js` 提供：
  - `appShell()`：手機版側欄開合與焦點歸還
  - `$store.toast`：全域提示（成功 2.5 秒、錯誤 5 秒）
  - `$store.search`：全站搜尋 Dialog（索引由 `_Layout` 注入，最多顯示 8 筆）
  - `trackReportClick()` + document 委派監聽：點擊埋點
  - `Ctrl/⌘ + K`：開啟搜尋
  - `window.zh`：簡繁轉換。`zh.match()` 供所有搜尋框做簡繁互通比對；cookie `rc_lang=zh-CN` 時整頁轉簡體（見 `docs/02` §1.8）
  - `window.catBadge()`：依分類名稱雜湊選色（5 色票需與 `Helpers/CategoryPalette.cs` 相同；部門頁優先用後端依序位指派的顏色）

更細的版面、元件、RWD 規格見 `ReportCenter.Web/docs/frontend-spec.md`；視覺規範見 `DESIGN.md`。
