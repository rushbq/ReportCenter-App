# 內部站台登入規格（DataHubApi JWT + 站台 Cookie）

ReportCenter、PKWeb.Admin、HomeWebApp 共用這份規格，取代 IIS Windows 驗證。ReportCenter 是第一個實作的站台，程式可以直接參考。

## 目標

- 所有內部站台都不再依賴 Windows 驗證，Mac、手機、非網域電腦都能登入。
- 帳密驗證與 Refresh Token 由 DataHubApi 統一負責，和 PKPortal 共用。**在任何一個站登入過，其他站就不用再登入。**
- 在任何一個站登出，所有站一起登出。

## 運作方式

```
瀏覽器                        站台 (ReportCenter 等)                DataHubApi
  │ GET /Favorites ──────────► 沒有站台 Cookie → 302 /Account/Login
  │ 登入頁 JS ─── POST /api/Auth/Refresh (帶 dh_rt Cookie) ─────────► 200 { data.token }
  │ POST /Account/Login?handler=SignIn (token) ─► 用公鑰驗證 JWT
  │                             ◄─ Set-Cookie 站台 Cookie，導回原頁
  │ （Refresh 失敗才顯示帳密表單 → POST /api/Auth/Login → 同樣送 SignIn）
```

- **身分**：JWT 的 `name` claim 是工號。站台 Cookie 中的 `ClaimTypes.Name` 也放工號，現有以 `User.Identity.Name` 解析身分的程式不用改。
- **JWT 驗證**：RS256，用 DataHubApi 的**公鑰**驗證，並檢查 Issuer=`DataHubApi`、Audience=`PKPortal`、有效期限（ClockSkew 1 分鐘），只接受 `RS256`。公鑰不是機密，放在 appsettings。
- **密碼不經過站台伺服器**：登入表單直接送到 DataHubApi。表單用真正的 `<form>`，並設定 `autocomplete="username"`、`current-password`，讓瀏覽器和 Mac 鑰匙圈可以記住帳密。
- **免登入的條件**：站台和 DataHubApi 都要用 `https://*.prokits.com.tw` 開啟，兩者才算同一個站，瀏覽器才會送出 `SameSite=Strict` 的 `dh_rt`。用 IP、主機名稱或 http 開啟時，會改顯示帳密表單。

## 站台必須做到的事

| 項目 | 規格 |
|------|------|
| 驗證機制 | `AddCookie`。Cookie 名稱各站不同（`rc_auth`、`pkadmin_auth`、`home_auth`），`HttpOnly`、`Secure`、`SameSite=Lax`，8 小時，有使用就延長 |
| 未登入 | 一般換頁（`Sec-Fetch-Mode: navigate`）302 到 `/Account/Login?ReturnUrl=…`；**其他請求（fetch、XHR、htmx、sendBeacon）回 401** |
| 前端 401 | 收到同源 401 時重新整理頁面，就會自動走一次登入流程。fetch 用包裝函式，jQuery 用 `ajaxError`，htmx 用 `htmx:responseError` |
| 授權 | `FallbackPolicy` 要求已登入，所有環境都套用。登入頁、登出、錯誤頁、靜態檔設為 `AllowAnonymous` |
| 登入頁 | 不使用網站共用版型（共用版型會查資料庫、取目前使用者）。`returnUrl` 只接受站內網址 |
| SignIn | 需要 Antiforgery。JWT 無效時回 401 JSON，並寫 Warning log（只記例外類型，**不記 Token**） |
| 登出 | ① POST 站台 `/Account/Logout` ② POST DataHubApi `/api/Auth/Logout`（`credentials: 'include'`）③ 導向 `/Account/Login?loggedOut=true`，此時不做自動登入 |
| Data Protection | 金鑰存到固定資料夾（`DataProtection:KeysPath`），Windows 上用 DPAPI（machine）保護。沒有設定的話，App Pool 回收後所有人都會被登出 |
| 開發環境 | 保留模擬身分，只在「有設定模擬帳號、而且目前未登入」時注入。清空模擬帳號，就能在本機測試真正的登入頁 |
| IIS | 只開匿名驗證、關閉 Windows 驗證；不要在 `web.config` 寫 `<authentication>`（會出現 500.19） |

## 設定

```json
"DataHubAuth": {
  "ApiBaseUrl": "https://datahubapi.prokits.com.tw/api",   // 測試區：https://dhtest.prokits.com.tw/api
  "Issuer": "DataHubApi",
  "Audience": "PKPortal",
  "PublicKeyPem": "-----BEGIN PUBLIC KEY-----\n...\n-----END PUBLIC KEY-----",
  "CookieHours": 8
},
"DataProtection": { "KeysPath": "C:\\CompanySecrets\\keys\\<站台>" }
```

公鑰由 DataHubApi 管理者提供，產生方式見 DataHubApi 的 `docs/部署與設定.md`「JWT 金鑰對」。

## 已知限制

- 在 PKPortal 登出後，已經登入的站台最多還能再用 `CookieHours`（8 小時），因為站台 Cookie 是各站自己發的。
- 站台 Cookie 剛好過期時，`sendBeacon` 送出的使用記錄會漏掉那一筆（sendBeacon 收不到回應）。
- 本機用 `localhost` 測試時，和測試區的 DataHubApi 不是同一個站，無法測試免登入。本機測試請用 mock 或本機 DataHubApi，並且站台與 API 都用 http（或都用 https）。
